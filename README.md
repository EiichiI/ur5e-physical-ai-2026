# UR5e Physical AI Project 2026

## 1. プロジェクト概要

Physical AI講座2026 応用編1の最終課題として、AIの推論結果に基づいてロボットがタスクを実行するシステムの構築を目指します。

対象ロボットはUniversal Robots UR5eとRobotiq 2Fアダプティブグリッパーです。

## 2. 開発目標

1. 学習済みAIモデルで日本語の作業指示を推論する。
2. 推論結果に応じてロボットのタスクを選択する。
3. シミュレータ上でUR5eの動作を実行する。
4. 実行結果を動画として記録・評価する。

## 3. 使用技術と今後の構想

- 実装済み：Python、Google Colab、Hugging Face Sentence Transformers、MuJoCo、MuJoCo Menagerie
- シミュレーションモデル：Universal Robots UR5e、Robotiq 2F-85
- 未実装・今後の構想：ROS 2 Jazzy、MoveIt 2、実機制御

※ 第13～17節の開発段階・未実装の記述は、各実習当時の状況を示す。

## 4. システム構成（計画）

日本語指示 → AI推論 → タスク選択 → ロボット制御 → シミュレーション → 動画記録

## 5. 開発状況

第7回までにSentence Transformerによる日本語タスク選択と、MuJoCo上のUR5e・Robotiq 2F-85による円柱の把持、持ち上げ、搬送、配置、開放、待機姿勢復帰を統合して検証した（28.00秒・224フレーム）。第8回v06では新規の合成日本語指示72件について保存済み推論結果から2条件を比較した。ただし、正解ラベルは人間の最終確認前であり、精度評価は暫定。ROS 2および実機は未統合。

Google Colabで `07_ur5e_ai_pick_place_colab.ipynb` を開き、上から順に実行する。セル5でAIの判定を確認した後、セル6でシミュレーション・MP4・CSVを生成する。第8回v06の完全な再実行には `08_reliability_evaluation_v06.ipynb` と、第18節で示す新旧CSVが必要。Colabランタイムとライブラリバージョンによる再現性は提出前に要確認。

## 15. 第5回実習：UR5eとRobotiq 2F-85による円柱試料の把持・持ち上げ

### 15.1 開発目的

第4回実習では、日本語指示のAI推論、UR5eの姿勢制御、Robotiq 2F-85の開閉制御を統合した。

第5回実習では、これを物体操作へ発展させるため、MuJoCo上に円柱試料を配置し、グリッパーによる接触把持と持ち上げ動作を試作・検証した。

本実習は開発途中の基礎検証であり、搬送先への移動や配置までを行う完全なPick & Placeシステムではない。

### 15.2 実験システムと試料条件

**実行環境**

- Google Colab
- Python
- MuJoCo
- Universal Robots UR5e
- Robotiq 2F-85アダプティブグリッパー

**試料条件（シミュレーション設定値）**

| 項目 | 設定値 |
|---|---|
| 試料形状 | 円柱 |
| 試料直径 | 32 mm |
| 試料高さ | 56 mm |
| 試料質量 | 30 g |
| 持ち上げ目標高さ | 75 mm |
| 支持台 | 円柱試料の下部に配置 |

円柱にはMuJoCoの自由関節（freejoint）を設定し、グリッパーに固定しない自由物体として扱った。

したがって、試料の上昇にはグリッパーと試料との物理的な接触・摩擦による保持が必要となる。

### 15.3 実装内容

以下の5段階の動作を実装した。

1. **SETTLE_OPEN**：グリッパーを開いた状態で、円柱試料を支持台上に静置する。
2. **CLOSE**：グリッパーを閉じ、左右の指パッドを試料に接触させる。
3. **GRASP_HOLD**：グリッパーを閉じたまま保持する。
4. **LIFT**：逆運動学で計算した関節目標へUR5eを移動させ、試料を約75 mm持ち上げる。
5. **HOLD_UP**：上昇後の姿勢を維持し、試料の保持状態を確認する。

持ち上げ目標姿勢は、UR5eのヤコビアンを使用した数値逆運動学により求めた。

シミュレーション中は、試料位置、支持台からの離隔距離、左右パッドの接触状態、接触法線力、ロボット関節の目標追従誤差を記録した。

### 15.4 実験結果

約9.75秒のシミュレーションを実行し、78フレームの動作記録を取得した。

**動作段階別の結果**

| 動作段階 | 終了時刻 | 試料高さ | 両パッド接触 |
|---|---:|---:|---|
| SETTLE_OPEN | 1.25秒 | 331.354 mm | False |
| CLOSE | 4.25秒 | 331.385 mm | True |
| GRASP_HOLD | 5.25秒 | 331.650 mm | True |
| LIFT | 8.25秒 | 406.087 mm | True |
| HOLD_UP | 9.75秒 | 407.686 mm | True |

**主要な評価結果**

| 評価項目 | 結果 |
|---|---|
| 持ち上げ目標高さ | 75 mm |
| 静置後からの試料上昇量 | 約76.3 mm |
| 最終的な支持台からの離隔距離 | 約76.0 mm |
| 閉動作以降の両パッド接触 | 68/68記録 |
| 上昇後の保持時間 | 約1.5秒 |
| 最終時点の左パッド接触法線力 | 約45.3 N |
| 最終時点の右パッド接触法線力 | 約45.3 N |
| 最終関節目標追従誤差 | 約0.011 rad |

※接触法線力はMuJoCoモデルから得られた値であり、実機の把持力測定結果ではない。

動画とCSVログから、オレンジ色の円柱試料が緑色の支持台から離れ、左右の指パッドに保持された状態で上昇していることを確認した。

### 15.5 実験結果の評価

今回の設定条件では、Robotiq 2F-85による円柱試料の接触把持と約75 mmの持ち上げ動作を実現できた。

試料はグリッパーに固定されておらず、接触計算を通じて保持されている。

また、上昇後の保持段階でも左右パッドの接触が継続し、試料が支持台へ落下しなかった。

以上より、**今回設定したMuJoCoシミュレーション条件における基本的な把持・持ち上げ試験は成功した**と判断した。

ただし、これは単一の試料・把持条件における初期実験結果であり、実機での動作や把持性能を保証するものではない。

### 15.6 現段階の制約と技術的課題

今回の試作システムには、以下の課題が残っている。

1. **把持力の妥当性検証**：シミュレーション上ではパッドごとに約45 Nの接触法線力が記録された。実機仕様や試料の許容荷重を踏まえた検証が必要である。
2. **摩擦条件への依存性**：試料とパッドの摩擦係数を変えた場合の滑りや落下については未検証である。
3. **試料条件の一般化**：直径、質量、形状、材質を変えた場合の把持可能範囲は未評価である。
4. **搬送動作の未実装**：今回実施したのは垂直方向への持ち上げまでであり、水平搬送・下降・配置は行っていない。
5. **位置認識の未実装**：試料位置は既知の条件として設定した。カメラ画像やセンサーからの位置認識は行っていない。
6. **AIとの統合が未完了**：第5回実習の把持・持ち上げ動作は、事前に設定した動作系列に基づく。自然言語指示から把持位置や運動軌道をAIが自動生成するものではない。
7. **安全性・再現性の検証不足**：外乱、接触条件のばらつき、衝突、複数回の試行による成功率などの検証が必要である。

## 18. 第8回実習：日本語作業指示の信頼性評価（v02～v06）

### 18.1 目的と位置づけ

第7回の日本語タスク選択機構を対象に、学習済みSentence Transformer（`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`）と規則ベースの実行許可／拒否ゲートの動作を検証した。AIは定義済みの作業IDを選択するのみであり、把持位置・関節軌道・物理運動を生成しない。第8回はテキスト分類性能の評価であり、MuJoCoの新たな動作試験ではない。

v02～v05では開発用72指示を使用して誤判定を調べ、v05で閾値候補を選定した。v06では、旧72件と文面が重複しない新しい合成日本語指示72件を用い、2条件の性能を比較した。閾値はv06評価前に定められた設定であり、v06の予測結果を使って再調整していない。

### 18.2 評価データと比較設定

- 新規評価データ：72件（`MOVE_LEFT_TO_RIGHT` 24件、`HOME` 24件、`REJECT` 24件）
- データの性質：人工的に作成した合成指示。実際の現場指示を無作為抽出したものではない。
- 正解ラベル：事前提案ラベル。**人間による最終確定前であり、以下の評価値は暫定**。
- 条件A（v04基準）：類似度閾値 0.600、上位候補間margin閾値 0.025
- 条件B（v05開発データによる候補）：類似度閾値 0.350、margin閾値 0.010
- 両条件とも、否定・停止・未対応作業等の優先拒否ルールを適用した。
- 新規評価データのSHA-256：`d8ab45ff83325c4c26a457eef26d29f07735d349fe1a903752dc908144bd029c`

### 18.3 評価結果（保存CSVの集計による暫定値）

| 評価項目 | A：v04基準 | B：v05改善候補 |
|---|---:|---:|
| 正答数・正答率 | 38/72（52.8%） | 44/72（61.1%） |
| MOVE指示の正答 | 5/24 | 5/24 |
| HOME指示の正答 | 12/24 | 19/24 |
| REJECT指示の正答 | 21/24 | 20/24 |
| 本来REJECTすべき指示の誤受理 | 3/24 | 4/24 |
| 正当な指示の過剰拒否 | 31/48 | 24/48 |
| 本来MOVE以外の指示に対するMOVE許可 | 3件 | 4件 |

条件Bは条件Aより正答率が約8.3ポイント高いが、正答の増加は主にHOME認識（+7件）による。MOVE指示の正答数は変わらず、REJECTをMOVEとして誤って許可した件数は1件増加した。このため、**条件Bが安全面を含めて優れているとは結論できない**。

### 18.4 主要な誤判定と制約

否定・中断・引用文のように、文中に搬送の語が含まれていても実行を許可すべきでない指示で、誤受理を確認した。例：`左の円柱を右の青台に運んではいけないという指示です`。また、正当な搬送指示についても未認識・過剰拒否が多い。拒否規則の語彙範囲と、搬送元・搬送先の理解の双方が課題である。

評価対象は少数の合成テキストであり、精度・安全性の一般化はできない。旧72件での閾値選定結果は開発データ内の評価であり、v06の独立評価結果と混同しない。未実施の質量・摩擦係数45条件試験、ROS 2・実機試験についても実施済みとは記載しない。
